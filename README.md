# BofferElo

A React Native / Expo app for tracking ELO ratings in boffer combat. Targets iOS, Android, and web.

## Local Development

```bash
npm install          # Install dependencies
npx expo start       # Start dev server (scan QR with Expo Go, or press w/a/i)
npm run web          # Start web version only
npm run lint         # Run ESLint
```

Copy `.env.example` to `.env` and fill in your values before starting:

```bash
cp .env.example .env
```

## Deploying the Web App to Firebase Hosting

The web version is a static SPA built by Expo and deployed to Firebase Hosting via GitHub Actions. No Docker or server required.

### Why not Cloud Run Variables & Secrets?

Cloud Run's **Variables & Secrets** tab sets values at **runtime** — inside the already-running container. The `EXPO_PUBLIC_*` environment variables are **baked into the JS bundle at build time** by Expo's bundler. Runtime environment variables have no effect on the bundle once it is built.

Firebase Hosting solves this cleanly: the GitHub Actions workflow builds the app with secrets injected at build time and deploys the resulting static files directly.

### One-time setup

#### Step 1 — Install the Firebase CLI and log in

```bash
npm install -g firebase-tools
firebase login
```

#### Step 2 — Set your Firebase project ID

Edit `.firebaserc` and replace `YOUR_FIREBASE_PROJECT_ID` with your actual Firebase project ID (found in the Firebase Console under Project Settings).

#### Step 3 — Add GitHub Actions secrets

In your GitHub repository go to **Settings → Secrets and variables → Actions** and add the following secrets:

| Secret | Description |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | Your Supabase project URL, e.g. `https://xyz.supabase.co` |
| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Your Supabase publishable (anon) key |
| `EXPO_PUBLIC_API_URL` | The FastAPI backend URL, e.g. `https://your-api.run.app` |
| `FIREBASE_SERVICE_ACCOUNT` | Firebase service account JSON (see step 4) |
| `FIREBASE_PROJECT_ID` | Your Firebase project ID |

#### Step 4 — Generate the Firebase service account

This gives GitHub Actions permission to deploy to Firebase:

```bash
firebase init hosting
```

When prompted, select your project. This also lets you run the following to generate a CI service account token:

```bash
firebase init hosting:github
```

Follow the prompts — it will automatically create the `FIREBASE_SERVICE_ACCOUNT` secret in your GitHub repository.

### How it works

On every push to `main`, GitHub Actions:

1. Installs dependencies
2. Runs `npx expo export --platform web` with the secrets injected as environment variables — this bakes them into the JS bundle
3. Deploys the `dist/` folder to Firebase Hosting

### Manual deploy

To deploy from your local machine:

```bash
npm ci
npx expo export --platform web
firebase deploy --only hosting
```

Make sure your `.env` file is populated before running the export.

## Customising the Browser Tab Title and Favicon

### Tab title

The browser tab title is set at runtime in `app/_layout.tsx`:

```ts
document.title = 'BofferElo';
```

Change that string to update the title. The `name` field in `app.json` also sets the title in the static HTML shell generated by `expo export`, but the runtime value in `_layout.tsx` takes precedence once JavaScript loads.

### Favicon

The favicon is also set at runtime in `app/_layout.tsx` as an inline SVG data URI:

```ts
link.href = `data:image/svg+xml,${encodeURIComponent('<svg ...>⚔️</svg>')}`;
```

To change the favicon, edit that SVG string directly — no image file is required.

> **Why not `app.json`?**
> Expo's image pipeline (`@expo/image-utils`) does not support SVG files for `web.favicon`. The `app.json` field must point to a PNG (used for the native app icon pipeline). The runtime approach in `_layout.tsx` is the correct way to set an SVG or emoji favicon for the web build.
